# Cognito Integration Quick Reference

## Before & After Comparison

### Old JWT Authentication
```
signup/login → hash password → generate JWT → store token → use with API
```

### New Cognito Authentication  
```
signup/login → Cognito creates/verifies user → issue tokens → auto-refresh → use with API
```

## Environment Variables (Already Set)

```bash
COGNITO_USER_POOL_ID=<auto-generated>
COGNITO_CLIENT_ID=<auto-generated>
COGNITO_REGION=us-east-1
```

## Frontend - No Changes Needed ✅

The `script.js` file automatically:
- Sends credentials to Cognito endpoints
- Stores and refreshes tokens
- Includes tokens in API requests
- Handles token expiration

## Backend - Handler Changes

### Before (JWT)
```javascript
const { hashPassword, generateToken } = require('../utils/auth');
// Manual password hashing
// Manual JWT generation
```

### After (Cognito)
```javascript
const AWS = require('aws-sdk');
const cognito = new AWS.CognitoIdentityServiceProvider();
// Cognito handles everything
```

## API Handler Pattern

### Old Pattern
```javascript
// Extract userId that client sent
const userId = body.userId;

// Verify JWT manually  
const token = parseJWT(header);
```

### New Pattern
```javascript
// Extract from Cognito authorizer context
const authorizer = event.requestContext?.authorizer;
const userId = authorizer?.claims?.sub;
const email = authorizer?.claims?.email;
```

## Cognito Error Codes

```javascript
if (error.code === 'UsernameExistsException') {
    // Email already registered
}
if (error.code === 'InvalidPasswordException') {
    // Password doesn't meet requirements
}
if (error.code === 'NotAuthorizedException') {
    // Invalid credentials
}
if (error.code === 'UserNotConfirmedException') {
    // User not confirmed (shouldn't happen - auto-confirm enabled)
}
```

## Token Structure

### Access Token
- **Type**: JWT
- **Purpose**: API authorization
- **Lifetime**: 1 hour (configurable)
- **Used For**: Include in `Authorization: Bearer {token}`

### ID Token  
- **Type**: JWT
- **Purpose**: User identity
- **Lifetime**: 1 hour
- **Contains**: User claims (email, name, etc.)

### Refresh Token
- **Type**: Opaque string
- **Purpose**: Get new access/ID tokens
- **Lifetime**: 30 days (configurable)
- **Used For**: Refresh endpoint only

## Common Operations

### Sign Up
```bash
POST /auth/signup
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePassword123",
  "firstName": "John",
  "lastName": "Doe",
  "phone": "+1234567890"
}

Response:
{
  "success": true,
  "message": "User registered successfully",
  "data": {
    "userId": "us-east-1_xxxxx:user-uuid",
    "email": "user@example.com",
    "firstName": "John",
    "lastName": "Doe"
  }
}
```

### Login
```bash
POST /auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePassword123"
}

Response:
{
  "success": true,
  "message": "Login successful",
  "data": {
    "userId": "us-east-1_xxxxx:user-uuid",
    "email": "user@example.com",
    "firstName": "John",
    "tokens": {
      "accessToken": "eyJkb2N...",
      "idToken": "eyJkb2N...",
      "refreshToken": "eyJkb2N..."
    }
  }
}
```

### Refresh Token
```bash
POST /auth/refresh
Content-Type: application/json

{
  "refreshToken": "eyJkb2N..."
}

Response:
{
  "success": true,
  "message": "Tokens refreshed successfully",
  "data": {
    "tokens": {
      "accessToken": "eyJuZXc...",
      "idToken": "eyJuZXc..."
    }
  }
}
```

## Debugging Tips

### Check if User Exists in Cognito
```bash
# Via AWS CLI
aws cognito-idp admin-get-user \
  --user-pool-id us-east-1_xxxxx \
  --username user@example.com \
  --region us-east-1
```

### List All Users in User Pool
```bash
aws cognito-idp list-users \
  --user-pool-id us-east-1_xxxxx \
  --region us-east-1
```

### Check Deployment Status
```bash
serverless info

# Shows:
# - Service, Stage, Region
# - API Gateway URL
# - Lambda functions
# - CloudFormation stack name
```

### View CloudWatch Logs
```bash
# For auth functions
serverless logs -f signup
serverless logs -f login
serverless logs -f refresh

# Watch logs in real-time
serverless logs -f login -t
```

## Password Requirements

Current policy (configurable in serverless.yml):
- **Minimum length**: 8 characters
- **Uppercase**: At least one A-Z
- **Lowercase**: At least one a-z  
- **Numbers**: At least one 0-9
- **Symbols**: Not required (can add)

Example valid password: `MySecure123`
Example invalid: `password` (no uppercase, no numbers)

## Limitations & Gotchas

1. **Password Reset**: Not yet implemented (future enhancement)
2. **Email Verification**: Disabled (auto-verified for dev convenience)
3. **MFA**: Not enabled (can be enabled in Cognito console)
4. **Social Login**: Not configured (can add Google, Facebook, etc.)
5. **Token Expiration**: Fixed 1-hour for access token

## Performance Notes

- Token refresh is automatic and transparent to user
- Cognito calls are fast (<100ms typically)
- No database queries for authentication (Cognito manages this)
- Authorizer runs on each API request (caches results)

## Security Checklist

- ✅ Passwords never stored in your database
- ✅ Tokens expire automatically  
- ✅ HTTPS enforced (API Gateway, Cognito)
- ✅ Token refresh prevents long-lived tokens
- ✅ Password policy enforced (no weak passwords)
- ✅ User identity verified by Cognito (can add email verification)
- ✅ API requests must include valid access token
